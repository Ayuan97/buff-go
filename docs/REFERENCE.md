# 语义参考

本文维护控制台、领域模型和持久化共同使用的稳定语义。当前只有 Steam 具备采集执行能力。

## 商品身份与方向

| 术语 | 语义 |
| --- | --- |
| `product_id` | 系统内部稳定的 Steam 标准商品 ID |
| `appid` | Steam 游戏或应用范围 |
| 平台商品 ID | 平台返回的商品标识 |
| 平台映射 | 平台商品身份与标准商品之间的关联 |
| `ask` | 出售方向；搜索并记录最低出售价 |
| `bid` | 求购方向；读取订单簿并记录最高求购价 |

Steam 出售搜索是商品发现入口。搜索页提交时，系统按以下顺序确定商品：

1. 采集结果带有已知 `product_id` 时，校验它属于当前 `appid` 后使用。
2. 平台商品 ID 已有映射时，使用该映射。
3. 在同一 `appid` 内按完全一致的名称查找；唯一命中时使用，一条都没有时创建新商品，多条命中时拒绝整页。

名称匹配不做模糊匹配、跨游戏匹配或本地化名称猜测。求购方向只消费现有目录，不发现新商品。

## 采集目标与任务

一个采集目标由 Steam 游戏、方向和采集条件组成。目标只有摘要采集；执行任务分为：

| 任务 | 语义 |
| --- | --- |
| `ask_page` | 一页 Steam 搜索结果，负责商品发现和最低出售价 |
| `bid_batch` | 一个现有目录商品，读取一次订单簿和最高求购价 |

系统为可运行方向维护持久的待执行任务集合，并记录下一扫描位置。队列深度是任务库存，不是并发数；实际速度由成功取得独立账号节点租约并领到任务的工人数决定。一个组合同时最多认领一条任务；同一账号同时最多执行一条任务。组合完成后立即独立续领，不等待其他组合或下一次队列补货周期。运行期间超过认领时限的任务回到待执行集合，进程启动时全部遗留认领回队。

任务采用 at-least-once 投递：页面业务数据先作为整体提交，任务完成标记随后独立写入；若进程在两者之间中断，同一任务可以再次执行。

## 目标状态

目标同时保存使用者期望和后台实际状态：

| 层次 | 状态 | 含义 |
| --- | --- | --- |
| 使用者期望 | `enabled` | 希望系统持续采集 |
| 使用者期望 | `disabled` | 希望系统停止采集 |
| 后台实际 | `starting` | 已开启，正在等待执行条件成立 |
| 后台实际 | `running` | 正在执行 |
| 后台实际 | `waiting` | 临时失败，等待自动重试时间 |
| 后台实际 | `blocked` | 资源、限频或配置条件暂不满足 |
| 后台实际 | `stopping` | 正在清理未完成工作 |
| 后台实际 | `stopped` | 已完成停止 |
| 后台实际 | `error` | 不能自动恢复的调度异常；修复后关闭并重新开启 |

`waiting` 一定带下次检查时间并自动恢复。`blocked` 带下次检查时间时自动复查；没有下次检查时间时，需要修正配置后关闭并重新开启方向。

开启、关闭或修改采集条件会推进 `switch_version`。该版本区分不同启停周期，版本不匹配的在途结果不能覆盖当前目标。同一版本先比较真实请求的 `collected_at`，再用提交时分配的 `write_seq` 打破同一微秒内的平局；较早发出的请求即使更晚返回，也不能覆盖较新的行情。

## 账号、节点与组合

| 术语 | 语义 |
| --- | --- |
| 账号 `valid` | 已由成功采集确认可用 |
| 账号 `unverified` | 凭据已录入或替换，等待成功采集确认 |
| 账号 `invalid` | 会话失效，不能继续工作 |
| `direct` | 直连节点 |
| `proxy` | 代理节点 |
| `static` | 固定出口模式 |
| `sticky` | 在一段代理会话内保持出口的模式 |
| `domestic` | 国内地域；Steam 不使用 |
| `foreign` | 国外地域；Steam 可使用 |
| `hongkong` | 香港地域；Steam 可使用 |
| 出口证据 | 人工记录的公网出口 IP、验证时间与有效期 |
| 组合 | 一个账号与一个节点的持久绑定 |

健康组合要求账号未失效、节点出口证据未过期，并且节点地域允许该平台。Steam 只使用 `foreign` 和 `hongkong`。同一节点允许不同平台并行使用，但当前执行平台只有 Steam。

地域水位表示期望保留的最少可用代理数量。代理商与地域水位是配置数据，不代表已经存在可用代理节点，也不会触发自动获取或补充节点。

## 金额、数量与时间

- 进入统一行情的金额必须明确属于人民币，使用人民币分整数保存。
- 出售保存最低出售价，求购保存最高求购价，两者不能混用。
- `order_count` 表示当前方向的订单条数；`item_count` 表示这些订单包含的商品件数。平台没有明确语义时保持为空。
- `source_time` 是平台明确给出的数据时间；平台未提供时保持为空。
- `collected_at` 是持久限频准入完成、即将发送真实平台 HTTP 的时间；同一页里的商品共享这个时间。

## 行情状态与变价

统一行情身份为“标准商品 + 平台 + 方向”。同一身份分别保存最近一次明确尝试和最近一次有效价格：

| 状态 | 含义 | 当前有效价格 |
| --- | --- | --- |
| `present` | 平台明确返回可用行情 | 有 |
| `empty` | 平台明确返回该方向没有订单 | 无 |
| `unavailable` | 商品或方向不可访问 | 无 |
| `failed` | 已返回商品结果，但金额或响应语义无法安全接纳 | 无 |

网络、登录或整页解析失败会使任务回到库存，不批量写入行情失败状态。较新的尝试为空、不可用或失败时，最近有效价只作为带原采集时间的历史值保留。

只有有效价格数值变化才新增价格变化记录；订单数量变化不单独产生变价。查询窗口为最近 30 天。

## 最近提交批次

每个方向只保存最近一次成功提交的采集批次，不提供历史批次列表。ask 批次是一页搜索结果，bid 批次是一个商品的订单簿摘要。批次按开关版本、真实请求时间和提交写序选出最新值，并记录执行账号、出口地址和商品摘要。运行页把仍被保留的批次按账号与出口放到对应组合行；某方向由其他组合再次提交后，先前组合不再显示该方向的旧批次。

## 限频

限频引擎支持以下维度：

| 维度 | 语义 |
| --- | --- |
| 平台 | 同一外部平台的总体请求节奏 |
| 接口 | 出售搜索或求购订单簿的独立规则条件 |
| 账号 | 单个平台账号的请求限制 |
| IP | 单个公网出口的请求限制 |
| 账号与 IP | 特定账号和出口组合的请求限制；可再限定接口 |

一次真实外部请求必须同时通过全部适用规则。当前 Steam 不使用平台总频率桶；出售搜索和求购订单簿分别按“接口 + 账号 + 出口 IP”执行 2 秒固定间隔，互不占用额度。调度器会按当前实际工人数平滑同一平台接口的起跑时间，但不会把多个工人的额度重新合成一个全局上限。429 只更新本次请求所属接口、账号和出口 IP 的冷却状态，当前固定回退为 60 秒。2 秒与 60 秒都是保守运行参数，不代表已证明的平台绝对边界；不同平台使用各自策略和状态。
