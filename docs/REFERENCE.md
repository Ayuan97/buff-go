# 统一语义参考

本文只维护跨平台稳定的数据与状态语义。产品目标见 [README.md](../README.md)，模块关系见 [ARCHITECTURE.md](./ARCHITECTURE.md)，Web 操作方式见 [CONSOLE.md](./CONSOLE.md)，具体平台接口、登录、参数、返回和限频证据见 [`platforms/`](../platforms/README.md)。

## 商品身份

| 名称 | 含义 |
| --- | --- |
| `product_id` | 系统内部稳定的 Steam 标准商品 ID |
| `appid` | Steam 游戏或应用范围 |
| Steam 商品标识 | Steam 返回的 `market_hash_name` 等原始标识，具体组合以接口实测为准 |
| 平台商品 ID | BUFF、IGXE 等平台自己的商品标识 |

`product_id` 由 Steam 列表采集顺带创建：Steam 摘要页出现的商品在提交该页时写入标准目录，没有就新建，已有就更新可变字段。目录只增不减，商品是否仍在售由行情状态表达。

第三方商品映射顺序固定：

1. 采集条目自带 `product_id` 时直接使用，但该商品的 `appid` 必须与本次采集一致，否则整页提交被拒。
2. 条目带平台商品 ID 且已有映射记录时使用该映射。
3. 否则在同一 `appid` 内按完全一致的名称匹配已有商品：
   - 命中唯一一条时使用它；
   - 一条都没命中时按该名称新建标准商品，并在条目带平台商品 ID 时同时写入映射；
   - 命中多条时无法判定身份，整页提交被拒。

名称兜底不做模糊匹配，不跨游戏匹配，也不自动接受低置信结果。系统不保留「映射失败」这类中间状态：要么落到一个确定的 `product_id`，要么整页失败。

## 市场方向

系统内部只使用 `bid` 和 `ask`：

| 方向 | 中文 | 摘要值 | 含义 |
| --- | --- | --- | --- |
| `bid` | 求购 | `best_bid` | 当前最高求购价 |
| `ask` | 出售 | `best_ask` | 当前最低出售价 |

平台字段中的 `buy`、`sell`、推荐价、成交价或参考价不能仅凭名称映射。对应平台接口文档必须先证明字段属于哪个方向，以及是否确实为最优价。

## 采集任务类型

| 类型 | 是否有方向 | 含义 |
| --- | --- | --- |
| `summary` | 是，`bid` 或 `ask` | 周期采集平台列表摘要 |
| `detail` | 是，`bid` 或 `ask` | 规则命中后采集具体订单详情 |

标准商品目录不是一种任务类型。Steam 摘要采集读到的商品在提交该页时顺带写入目录：目录中没有就新建 `product_id`，已有就更新可变字段。因此不存在目录任务、目录开关和“立即同步目录”操作。

详情任务还必须满足对应 `(platform, side)` 的详情接口已经验证且适配器已经实现；不满足时只记录规则命中和 `detail_unavailable`，不创建执行任务。

## 金额与币种

- 进入统一行情的金额只允许人民币，币种代码为 `CNY`。
- 金额使用人民币分整数保存，不使用浮点数。
- 平台返回其他币种、币种缺失或单位无法确认时，数据不能进入可比较行情。
- 原始展示文本可以保留用于追查，但不能代替已经验证的金额与币种字段。
- 手续费是否包含在价格内属于平台接口语义，必须在对应接口文档中明确。

## 数量与时间

| 字段 | 含义 |
| --- | --- |
| `order_count` | 当前方向的订单条数 |
| `item_count` | 当前方向所有订单包含的商品件数 |
| `source_time` | 平台明确给出的数据时间；平台未提供时保持为空 |
| `collected_at` | 本系统完成采集的时间 |

平台只返回一个数量字段时，必须先确认它代表订单条数、商品件数还是累计深度。没有证据时不能同时填充两个字段。

## 行情状态

统一行情身份固定为 `(product_id, platform, side)`。同一身份同时维护两类事实：

- 最新采集尝试：最近一次明确请求得到的状态、开关版本、`write_seq`、时间和原因。
- 最近有效价格：最近一次 `present` 的价格和原始采集时间，只用于说明历史有效值。

| 状态 | 含义 | 是否有有效价格 |
| --- | --- | --- |
| `present` | 平台明确返回可用行情 | 是 |
| `empty` | 平台明确返回该方向当前没有订单 | 否 |
| `unavailable` | 接口不提供该方向或该商品无法访问 | 否 |
| `failed` | 请求、登录、解析或语义校验失败 | 否 |

空行情、不可用和失败都不能保存为价格 `0`。当较新的尝试为 `empty`、`unavailable` 或 `failed` 时，上次成功价格只能作为历史有效值展示，必须同时显示原采集时间和已非当前状态，不能伪装成本轮结果。

页面失败不能把未覆盖商品批量写成 `failed`、`empty` 或下架。只有平台明确返回的商品结果才可以更新对应身份状态。写入新旧顺序由 `(switch_version, write_seq)` 决定：已关闭版本和较旧 `write_seq` 不得覆盖较新的最新尝试或有效价格。`write_seq` 每成功提交一页加一，只增不减。

## 队列与工人

每个开启的方向有一条有序任务队列；账号加出口 IP 是临时工人。

| 概念 | 含义 |
| --- | --- |
| 方向队列 | 该方向待采任务，状态只有 `queued` / `claimed` |
| 补货 | 方向开着且有健康工人时，队列深度低于 100 就往队尾补；补完一圈从头再补，同页再出现等于下一圈，不去重 |
| 工人 | 一个账号绑到一个节点（出口 IP）；同一账号同时只打一枪 |
| 认领 | 工人从自己能干的方向里领入队最早的队头 |
| 当前页 | 每方向只留最新一页（账号、出口 IP、商品、原文），供运行页展示 |

没有健康工人时停止补货，已有任务可留。认领超时或工人死后，任务回到队头附近（入队顺序不变）。429 不丢任务，该工人冷却后再领。出售返回美元或 302 登录时标该账号失效，工人停领，任务回队。

第一版任务形状：出售是搜索一页；求购是目录里一批商品。以后换补货策略只改往队尾放什么。

详情任务仍由规则触发，且必须满足对应 `(platform, side)` 的详情接口已经验证且适配器已经实现；不满足时只记录规则命中和 `detail_unavailable`。

## 采集开关

采集开关按「游戏 + 平台 + 方向」控制。Steam 求购、Steam 出售、BUFF 求购、BUFF 出售等分别设置。规则自身控制详情触发。

关闭一个方向或改排序后：

1. 停止补货，丢掉该方向未完成任务。
2. 推进 `switch_version`，补货游标归零；`write_seq` 与已写入行情保留。
3. 实际状态先到 `stopping`，队列清空且占用释放后才是 `stopped`。

同一平台另一个仍开启的方向继续补货和认领。关闭某一游戏不影响其他游戏。

每个可控采集目标都必须同时展示两个维度：

| 维度 | 值 | 含义 |
| --- | --- | --- |
| 期望状态 | `enabled` / `disabled` | 使用者希望该采集目标是否运行 |
| 实际状态 | `starting` / `waiting` / `running` / `blocked` / `stopping` / `stopped` / `error` | 后台当前执行到了哪一步 |

`waiting` 表示已启用但正在等待下一周期或调度机会；`blocked` 表示因无可用组合、冷却或会话失效而暂时不能发出请求，必须同时提供原因和下一次自动判断时间或所需人工动作。`error` 只用于调度器自身无法维持该采集目标，不能代替正常等待或可解释的阻塞。

POST 操作成功只表示新的期望状态已经被接受，不表示所有在途请求和资源占用已经完成切换。例如关闭操作后可以出现 `disabled + stopping`，待被关闭方向的任务、在途请求和执行占用释放后才成为 `disabled + stopped`；不要求停止同平台另一个方向，也不因节点仍被其他平台使用而额外等待。

临时网络、平台错误或超时不丢任务；开关仍启用时，规划继续按水位补货，工人冷却后再领。登录失效或会话被标失效保持 `blocked`，直到使用者替换会话。无效配置或不可确认的接口语义不自动盲目重试。

## 账号与访问节点

| 概念 | 含义 |
| --- | --- |
| 平台账号 | 只属于一个交易平台的登录身份 |
| 访问节点 | 网络出口：本机直连或代理 |
| 节点时效 | `stable` 长效，或 `short` 短效池化代理 |
| 节点地域 | `domestic`、`foreign`、`hongkong`；本机也必须配置 |
| 实际出口 IP | 最近验证的公网出口；**有效期内 IP 不变**；限频键用「平台 + 出口」等 |
| 出口验证有效期 | 超过后须重验才可派发（长效）；短效过期或探测失败则丢弃 |
| 代理商 | 可配置多家；各商声明能供哪些地域，按优先级拉号 |
| 短效地域水位 | 按地域配置「最少可用短效数」；低于则向能供该地域的商补到该数 |
| 账号节点组合 | 该平台账号绑到一个节点；采集时只校平台与地域 |
| 执行占用 | 工人认领一条任务期间独占该组合 |

### 节点属性

- **长效**：固定出口，IP 在有效期内不变；有固定失效/验证窗；到期停用，不自动扔货。
- **短效**：代理商池化 IP，用着期间 IP 不变；寿命因商而异（如 3/5 分钟），**靠出口探测**确认；**出口/连接失败**才丢弃（禁止用「各平台业务都失败」当丢弃条件）。
- **地域**：国内 / 国外 / 香港；本机也须声明。
- **本机**：视为长效直连，须声明地域，不进短效补货水位。

### 平台 × 节点地域（强制）

接口目标只有国内站 / 国外站两档；节点能否派发看 `node.region` 是否允许该目标：

| 节点地域 | 可访问 |
| --- | --- |
| `domestic` | 仅国内站 |
| `foreign` | 仅国外站 |
| `hongkong` | 国内站 + 国外站 |

| 平台 | 目标线路 | 可用节点 |
| --- | --- | --- |
| Steam | 国外站 | `foreign`、`hongkong`（**禁止 `domestic`**） |
| BUFF、IGXE | 国内站 | `domestic`、`hongkong`（**禁止 `foreign`**） |

工人能否领某平台任务只看节点地域是否允许该平台目标线路。地域不符不得派发。

### 短效补货

- 水位只计 **短效且可用**（出口验证通过、非排空/退役、健康可派发）。
- 配置三地域各自 `minUsable`（最少可用数）；某地域可用短效少于最少时，向能供该地域且已启用的代理商按 **优先级** 拉号，补到该最少值。
- 新补节点只要出口可用、绑了对应平台账号、地域允许该平台，就可以被工人认领。
- 占用中的短效：先停新派发（排空），占用释放后再物理丢弃。

### 工人路由（强制）

组合能否干活只看：

1. 账号可用（会话 `valid` 或 `unverified`；`invalid` 停领）。
2. 节点可用（出口验证未过期）。
3. 节点地域允许该账号所属平台。

不配置手填「并行数」。并发 = 健康工人数。100 是方向队列备货水位，不是并发。想偏向某方向，就先给它补货；第一版不做单独优先级表。

### 执行与占用

- 请求使用「平台账号 + 节点」；认领到交回期间独占该组合，然后释放再领。
- 同一平台账号同时只服务一条任务。
- 同一节点可同时服务**不同平台**的账号（各平台各自限流）。
- 组合跨重启保存；认领占用写在队列表里。重启后 `queued` 还在，超时的 `claimed` 回队。删除账号或节点前须先解绑组合。

### 出口与健康

启用前验证出口 IP、验证时间与有效期。同平台内多节点同出口 → 共享该平台 IP 预算。节点 `validating` / `unavailable` 时，绑在该节点上的工人均不可领任务。

短效丢弃只看 **出口与连接探测**（含到期、验出口失败、连续连接失败），不把平台 429、Cookie 失效、业务错误算作代理死亡。

账号会话、代理认证、代理商 API 凭证：只写、查询脱敏、明文存 PostgreSQL。占用中不可换节点认证。首版不自动轮换账号。

## 限频与冷却

限频只在**单一平台**内生效，不得跨平台共用状态：

- 平台总预算（覆盖该平台全部外部请求，bid/ask 不分账；两侧同时抢额度靠工人数和补货偏向约束）。
- 接口类别。
- 平台账号。
- 平台 + 实际出口 IP。
- 平台 + 账号 + 出口 IP。

每次请求须命中该平台总规则与接口配置；账号/出口规则仅在证据支持时启用。一次准入在同一事务预占全部适用规则。429 只更新本平台证据范围；Steam 不得写入 BUFF/IGXE。

具体间隔与冷却数字属平台实测，不在本文维护。

## 平台接口证据状态

平台文档中的结论使用以下状态：

| 状态 | 含义 |
| --- | --- |
| 已观察 | 样本直接包含该字段或结果，但完整请求条件可能缺失 |
| 已验证 | 已保存脱敏后的请求条件和响应，且语义通过重复测试确认 |
| 待验证 | 来自文件名、旧说明、当前实现或单次推断，不能作为正式契约 |
| 冲突 | 不同样本或说明对同一字段给出不同含义 |

平台接入常驻采集前，至少要验证请求方法、参数、登录与人民币条件、分页、方向与价格口径、数量口径、空数据、错误格式、限频信号和冷却行为。
