# Web 控制台

本文定义 buff-go 目标 Web 控制台的操作流程和页面边界，不表示仓库当前已经实现这些页面。稳定业务术语见 [REFERENCE.md](./REFERENCE.md)，后端模块和交付方式见 [ARCHITECTURE.md](./ARCHITECTURE.md)。

控制台是私人采集系统的运维入口，面向系统所有者。界面采用克制、高密度、状态优先的工具型设计，首要目标是快速发现异常、准确分配资源和安全完成启停操作。

## 使用主线

1. 在概览中发现某个平台停止、数据过期、覆盖不完整或资源进入冷却。
2. 进入采集控制，确认平台求购或出售的期望状态与实际状态。
3. 进入资源，添加或维护平台账号、访问节点和明确的账号节点组合。
4. 返回采集控制开启任务，观察它从启动中进入运行中。
5. 在运行中查看当前任务、分页位置、覆盖完整性、资源占用和限频原因。
6. 在市场数据中按 Steam 标准商品查看跨平台人民币求购与出售行情及映射结果。
7. 需要进一步判断时，进入规则与详情查看触发依据和详情快照。

## 页面结构

| 页面 | 回答的问题 | 核心内容 | 主要操作 |
| --- | --- | --- | --- |
| 概览 | 系统现在是否正常 | 平台方向状态、数据新鲜度、异常运行、冷却资源、映射失败 | 跳转到对应问题 |
| 采集控制 | 哪些目录和行情应该采、实际上是否在采 | Steam 目录同步、平台 × bid/ask 开关、期望状态、实际状态、最近运行 | 开启、关闭、立即同步目录 |
| 资源 | 账号和访问节点如何使用 | 平台账号、访问节点、地域、平台独占分配、账号节点组合、占用 | 添加、删除、分配、解除、绑定 |
| 运行 | 任务为什么慢、停或不完整 | 运行批次、页游标、覆盖范围、资源占用、限频与冷却原因 | 查看诊断、进入关联资源或行情 |
| 市场数据 | 当前采到了什么 | Steam 标准商品、平台映射、`best_bid`、`best_ask`、数量、时间、状态 | 筛选、查看映射失败、进入商品详情 |
| 规则与详情 | 哪些摘要触发了进一步采集 | 规则状态、触发依据、详情任务、详情快照完整性 | 启停规则、查看详情结果 |

首版使用固定的一级导航，不把账号、代理、任务和行情拆成大量孤立页面。账号、访问节点和账号节点组合属于同一个“资源”工作区；限频与冷却属于“运行”诊断，不单独制造配置中心。

## 关键操作

### 开启和关闭采集

Steam 商品目录同步按 `appid` 展示不带方向的独立行，包括开关、周期、最近成功和“立即同步”操作。它不随 Steam 求购或出售关闭而停止。立即同步只在目标启用时可用；已有活动运行时显示并进入该运行，不再创建第二轮。修改周期从下一轮生效。

每个平台分别展示求购和出售。开关旁必须同时显示期望状态和实际状态：开启后可以处于“启动中”“等待中”“运行中”或“已阻塞”；无可用资源、冷却和登录失效属于带原因的阻塞，不显示为错误。关闭后先进入“停止中”，待被关闭方向的任务、在途请求和执行占用释放后才显示“已停止”，不要求同平台另一个方向停止。

关闭确认说明应明确：系统停止创建新请求并取消可以取消的请求，已经保存的数据不会被删除。页面不能在 POST 返回后立即伪装成已停止。

### 管理账号与访问节点

平台账号至少展示别名、所属平台、会话状态、最近验证时间和当前占用；保存后不在列表和查询接口中返回原始会话内容。会话失效后由使用者明确替换，首版不自动轮换。删除或替换正在被请求使用的账号前，必须先停止相关任务并释放占用。

访问节点至少展示名称、连接类型、本机或代理、地域能力、实际出口 IP、最近验证时间、验证有效期、健康状态、当前平台分配和占用。国内节点只能用于国内接口，国外节点只能用于国外接口，香港节点可以用于两类接口；本机直连同样必须选择地域能力。

节点由平台独占分配。第一版不自动跨平台借用，也不自动把平台下所有账号和节点组合。使用者明确建立一个“平台账号 + 访问节点”组合，系统再把它作为可占用执行资源。

资源页必须分别展示已分配节点数、可用账号数、可用组合数和当前有效并发数，并解释限制原因。分配两个节点但只有一个可用账号时，不能把并发能力显示成二；额外节点只有在存在额外账号组合和可并行任务时才能提高吞吐。

多个节点验证为同一出口 IP 时，页面必须提示它们共享 IP 预算，不能按节点数量累加吞吐。验证过期或代理配置、凭据、粘性会话变化时显示“重新验证中”并停止派发；出口变化或无法稳定识别时，节点显示为待重新验证或不可用，不能继续使用旧 IP 预算。

### 查看运行与冷却

运行列表必须同时展示运行状态和覆盖完整性。`failed + partial`、`stopped + partial` 都是有效组合，不能简化成一个模糊的红色“失败”。

运行详情至少能追到平台、方向、开始与结束时间、当前分页位置、成功页范围、使用的账号节点组合、最后错误和冷却截止时间。等待和阻塞必须显示原因、下一次自动判断时间或所需人工动作。首版只提供只读诊断，不允许从页面强制清除冷却或绕过限频。

### 查看行情与映射

市场数据以 Steam 标准商品为中心，一行展示各平台可比较的人民币行情。求购明确显示“最高求购价”，出售明确显示“最低出售价”，同时显示采集时间、最新尝试状态和本轮完整性。最新尝试失败、为空或不可用时，最近有效价格只能作为带原时间的历史值展示，不能保持成看似正常的当前价格。

映射失败单独列出平台商品、平台标识、候选 Steam 标识或名称以及失败原因。首版不提供模糊匹配和批量自动确认，只展示自动精确映射结果与失败项。

### 查看规则与详情

规则只对有效摘要运行。规则页展示规则是否启用、条件版本、最近触发时间和详情任务结果；详情页展示指定平台、商品和方向的订单快照、采集时间和完整性。部分快照必须显著标明，不能覆盖最近一次完整结果。

## 状态呈现

所有数据页面都必须处理以下界面状态：

- 加载中：保留页面结构并明确当前正在读取什么。
- 空状态：说明是尚未配置、确实没有数据，还是筛选后无结果。
- 错误状态：保留最近成功数据时，同时显示其时间和已过期状态。
- 禁用状态：说明操作为何不可用以及应先完成哪一步。
- 部分状态：明确已覆盖范围、未完成原因和最后成功时间。

颜色不能作为唯一状态信号；状态同时使用文字和必要图标。表单使用永久标签，不用占位文本代替字段名。主要表格支持紧凑筛选和稳定列顺序，避免卡片套卡片。

控制台以桌面浏览器为主要使用环境。窄屏至少保证概览、采集停止和异常查看可用，但首版不为移动端重做完整资源分配工作流。

## 危险操作

以下操作必须先检查占用并要求明确确认：

- 关闭正在运行的采集方向。
- 解除或改变正在占用节点的平台分配。
- 删除或替换正在占用的平台账号。
- 删除正在占用的访问节点。
- 替换正在占用节点的代理认证信息。

确认框必须写明具体影响对象和后续状态，不使用笼统的“此操作有风险”。如果资源仍被占用，系统拒绝删除或重分配，并提供关联任务入口，不能后台强行拆除。

## 本地控制面安全

控制台只加载同源静态资源，不使用 CDN 或第三方脚本。所有读取使用无副作用 GET；所有修改使用 JSON POST，并携带服务端提供的 CSRF 令牌。后端同时校验 `Host` 和同源 `Origin`，不开放跨域响应，避免恶意网页借浏览器访问本机控制接口。

查询页面和浏览器日志不得出现原始账号会话、代理密码或解密密钥。账号会话与代理认证信息只在新增或明确替换时提交；保存后页面只显示别名、状态、最近验证时间和占用信息。

控制台首次加载时从同源安全上下文 GET 取得短期 CSRF 令牌；服务端同时设置 `HttpOnly`、`SameSite=Strict` 控制会话 Cookie。生成的 TypeScript 客户端统一把令牌放入专用请求头。会话或令牌过期后重新获取，业务 POST 不静默重放。

## 首版范围

首版必须完成：

- 平台 × 求购/出售的独立开关，以及期望、等待、运行、阻塞、停止和错误状态。
- Steam 商品目录同步的独立开关、周期、立即同步和运行状态。
- 平台账号、访问节点、本机直连、平台独占分配和显式账号节点组合。
- 运行批次、分页游标、覆盖完整性、错误和只读冷却诊断。
- 以 Steam 商品为中心的跨平台人民币摘要行情和映射失败。
- 最小规则启停、触发记录和详情快照查看。
- 所有危险操作的占用检查、确认和真实停止状态。
- 本机访问下的 Host、Origin、CSRF、CSP 和敏感字段保护。

首版不做：

- 桌面客户端或额外 Node 后端。
- 节点跨平台自动借用、账号自动轮换和智能资源调度。
- 手动清除冷却、绕过限频或自动探测全部平台频率。
- 模糊商品映射、批量自动确认和复杂可视化规则编辑器。
- 趋势分析、套利利润、通知、多用户和权限系统。

## 页面验收标准

- 使用者能从概览定位到具体平台方向、运行、资源或映射异常。
- 开关操作不会把“已受理”误显示成“已完成”，也不会把等待或冷却显示成运行或错误；关闭后能看到该方向停止和执行占用释放过程。
- 使用者能完成账号、访问节点、平台分配和账号节点组合的完整维护流程。
- 被任务占用的账号或节点不能被直接删除或重新分配。
- 运行页面能解释任务使用了什么资源、完成到哪里、为何冷却或失败。
- 目录同步与摘要、详情任务能够按任务类型区分，目录失败不会被显示成某个市场方向失败。
- 关闭目录目标后立即同步不可用；重复立即同步不会产生并行重复运行，周期修改不会打断当前运行。
- 行情页面不混淆 bid/ask、时间、空数据、失败和部分覆盖。
- 首个页面接入真实 API，不使用演示数据、占位接口或仅前端保存的假状态。
- GET 无副作用，跨源请求和缺少 CSRF 的 POST 被拒绝，页面不加载第三方脚本或回显原始会话。
- 桌面与窄屏下没有遮挡、溢出和不可操作的关键停止入口。
