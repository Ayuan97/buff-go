# Web 控制台

本文定义 buff-go 目标 Web 控制台的操作流程和页面边界，不表示仓库当前已经实现这些页面。稳定业务术语见 [REFERENCE.md](./REFERENCE.md)，后端模块和交付方式见 [ARCHITECTURE.md](./ARCHITECTURE.md)。

控制台是私人采集系统的运维入口，面向系统所有者。界面采用克制、高密度、状态优先的工具型设计，首要目标是快速发现异常、准确分配资源和安全完成启停操作。

## 使用主线

1. 添加账号与节点（长/短效、地域、出口验证）。
2. 把节点分给游戏（例：香港节点 CS 2、Dota 3）。
3. 在每个游戏 × 平台下，把该游戏节点分给求购或出售。
4. 在概览按游戏开启各平台方向（不填并行数，用满已分配节点）。
5. 在运行看账号 + 出口 IP 在抓哪个游戏与方向。
6. 市场数据与规则按需查看。

## 关键操作

### 开启和关闭采集

概览按游戏组织：每个游戏下 Steam / BUFF / IGXE 的求购与出售开关与实际状态。不提供手填并行；界面可显示该方向已分配节点数 / 当前在用。无可用节点、冷却、会话失效为阻塞。关闭后先停止中再已停止。POST 受理不等于已停止。

### 节点分配

1. **游戏配额**：把节点划入 `appid`（数量或明确名单）。  
2. **游戏 × 平台 × 方向**：在该游戏节点中，为 Steam/BUFF/IGXE 分别指定求购用哪些、出售用哪些；同平台同游戏下两侧不共享同一节点。  
3. 游戏内多平台共用同一批游戏节点，但 **划方向时受地域约束**：Steam 仅国外/香港节点；BUFF/IGXE 仅国内/香港节点。国内节点不可划给 Steam；国外节点不可划给 BUFF/IGXE。  
4. 平台限流各自独立。

### 账号与节点资料

账号：别名、平台、会话状态、占用；不回显会话。占用中不可删号或换会话。

节点：名称、本机/代理、长效/短效、地域、出口 IP、验证与有效期、健康、来源（手工/代理商）。有效期内 IP 不变。验证中/不可用则任何游戏与方向不可用该节点。短效出口探测失败 → 排空后丢弃。

占用按「游戏 × 平台 × 方向 × 账号 × 节点」展示。同平台内同出口多节点提示共享该平台 IP 预算。

### 配置（短效补货）

短效池：按地域展示可用数 / 最少保留；可编辑国内、国外、香港的最少可用数。代理商：名称、启用、优先级、可供地域（凭证只写不回显）。与资源页分离，避免日常分配与供应商配置搅在一起。

### 查看运行

以 **账号 + 出口 IP** 为单元，标明游戏、平台、方向。展示在跑/空闲、抓取进度、错误或冷却。同一出口上不同平台任务分开展示。只读诊断，不可清冷却。

### 查看行情与映射

市场数据以 Steam 标准商品为中心，一行展示各平台可比较的人民币行情。求购明确显示“最高求购价”，出售明确显示“最低出售价”，同时显示采集时间、最新尝试状态和本轮完整性。最新尝试失败、为空或不可用时，最近有效价格只能作为带原时间的历史值展示，不能保持成看似正常的当前价格。

映射失败单独列出平台商品、平台标识、候选 Steam 标识或名称以及失败原因。首版不提供模糊匹配和批量自动确认，只展示自动精确映射结果与失败项。

### 查看规则与详情

规则只对有效摘要运行。规则页展示规则是否启用、条件版本、最近触发时间和详情任务结果；详情页展示指定平台、商品和方向的订单快照、采集时间和完整性。部分快照必须显著标明，不能覆盖最近一次完整结果。

## 状态呈现

所有数据页面都必须处理以下界面状态：

- 加载中：保留页面结构并明确当前正在读取什么。
- 空状态：说明是尚未配置、确实没有数据，还是筛选后无结果。
- 错误状态：保留最近成功数据时，同时显示其时间和已过期状态。
- 禁用状态：说明操作为何不可用以及应先完成哪一步。
- 部分状态：明确已覆盖范围、未完成原因和最后成功时间。

颜色不能作为唯一状态信号；状态同时使用文字和必要图标。表单使用永久标签，不用占位文本代替字段名。主要表格支持紧凑筛选和稳定列顺序，避免卡片套卡片。

控制台以桌面浏览器为主要使用环境。窄屏至少保证概览、采集停止和异常查看可用，但首版不为移动端重做完整资源分配工作流。

## 危险操作

以下操作必须先检查占用并要求明确确认：

- 关闭正在运行的采集方向。
- 删除或替换占用中的平台账号。
- 删除占用中的访问节点，或替换其代理认证。
- 改动占用中节点的游戏配额或 bid/ask 归属。

确认框写明影响对象与后续状态。仍被占用时拒绝删除或强改归属，并给出关联运行入口。

## 本地控制面安全

控制台只加载同源静态资源，不使用 CDN 或第三方脚本。所有读取使用无副作用 GET；所有修改使用 JSON POST，并携带服务端提供的 CSRF 令牌。后端同时校验 `Host` 和同源 `Origin`，不开放跨域响应，避免恶意网页借浏览器访问本机控制接口。

查询页面和浏览器日志不得出现原始账号会话或代理密码。账号会话与代理认证信息只在新增或明确替换时提交；保存后页面只显示别名、状态、最近验证时间和占用信息。

控制台首次加载时从同源安全上下文 GET 取得短期 CSRF 令牌；服务端同时设置 `HttpOnly`、`SameSite=Strict` 控制会话 Cookie。生成的 TypeScript 客户端统一把令牌放入专用请求头。会话或令牌过期后重新获取，业务 POST 不静默重放。

## 首版范围

首版必须完成：

- 节点按游戏配额，再按游戏 × 平台分给求购/出售。
- 概览按游戏启停各平台方向（无手填并行）。
- 账号、节点资料（长/短效、地域、出口验证）与占用展示。
- 短效池三地域水位与多代理商配置（样机可 mock；真拉号后置）。
- 运行页：账号 + 出口 IP、游戏、平台、方向、进度。
- 跨平台人民币行情与映射失败。
- 最小规则与详情快照。
- 危险操作占用检查与确认。
- 本机 Host、Origin、CSRF、CSP 与敏感字段保护。

首版不做：

- 桌面客户端或额外 Node 后端。
- 账号自动轮换。
- 真实代理商 API 拉号与探测闭环（样机先露水位与配置）。
- 手动清冷却、绕过限频。
- 模糊映射与复杂规则编辑器。
- 趋势、套利、通知、多用户权限。

## 页面验收标准

- 能把节点分到游戏，再分到各平台求购/出售；游戏内多平台共用游戏节点池。
- 概览只开关、不填并行；已分配节点用满（受健康、账号、限频约束）。
- 开关不把受理当完成；关闭可见停止过程。
- 占用中的账号、节点不可强删。
- 运行页能说明账号、出口 IP、游戏、平台、方向、进度与失败原因。
- 行情不混淆 bid/ask、空/失败、部分覆盖。
- 真 API 接通后不使用演示数据冒充完成。
- GET 无副作用；缺 CSRF 或跨源 POST 拒绝；不回显会话原文。
