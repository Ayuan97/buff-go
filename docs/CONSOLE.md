# Web 控制台

本文定义 buff-go Web 控制台的操作流程和页面边界。稳定业务术语见 [REFERENCE.md](./REFERENCE.md)，后端模块和交付方式见 [ARCHITECTURE.md](./ARCHITECTURE.md)。

控制台是私人采集系统的运维入口，面向系统所有者。界面采用克制、高密度、状态优先的工具型设计，首要目标是快速发现异常、准确分配资源和安全完成启停操作。

## 使用主线

1. 添加账号与节点（长/短效、地域、出口验证）。
2. 把账号绑到节点。组合能否采只看平台和地域。
3. 在概览按游戏开启各平台方向（不填并行数，并发等于健康工人数）。
4. 在运行看账号 + 出口 IP 在抓哪个游戏与方向、当前页商品。
5. 市场数据与规则按需查看。

## 页面结构

| 页面 | 回答的问题 | 核心内容 | 主要操作 |
| --- | --- | --- | --- |
| 概览 | 各游戏开没开、卡在哪 | 游戏 → 平台 → 求购/出售；状态 | 加游戏、开/关、移除没跑过的方向 |
| 资源 | 账号与节点怎么配、还差什么 | 缺口清单；账号；扁平节点列表；节点上绑的账号 | 增删账号/节点、改名、填出口 IP、绑账号、换会话、换连接 |
| 配置 | 短效池水位与代理商怎么设 | 三地域最少可用短效；多代理商启停/优先级/地域/凭证 | 改水位、加商、改商（名称/优先级/地域/启停）、换凭证 |
| 运行 | 谁在跑、在抓什么 | 账号、出口 IP、节点、是否空闲、当前方向与当前页商品 | 只读 |
| 市场数据 | 采到什么价 | Steam 商品中心、各平台 bid/ask | 按游戏与平台筛选 |

固定一级导航。账号与节点的绑定在资源页；短效水位与代理商在配置页。

## 关键操作

### 开启和关闭采集

概览按游戏组织：每个游戏下 Steam / BUFF / IGXE 的求购与出售开关与实际状态。不提供手填并行；并发等于健康工人数。无健康工人、冷却、会话失效为阻塞。关闭后先停止中再已停止，未完成任务丢掉。POST 受理不等于已停止。

**移除方向**只用于撤销加错的游戏方向：必须已关闭且已停止，并且从来没跑过采集。跑过的方向只能关掉，界面会如实显示拒绝原因，采集历史不会因为想让按钮可用而被删除。

### 工人与节点

1. 组合就是账号绑到节点。  
2. 同一节点可以同时绑不同平台的账号，各平台限流互不影响。  
3. 工人路由 **受地域约束**：Steam 仅国外/香港节点；BUFF/IGXE 仅国内/香港节点。国内节点上的 Steam 账号不能领任务；国外节点上的 BUFF/IGXE 账号也不能。  
4. 节点参与采集的前提是记录了公网出口 IP 与有效期，本机直连同样要求；没记录时状态是待填出口 IP，调度不会用它。

### 账号与节点资料

账号：别名、平台、登录状态、最近检查；不回显会话。采集占用中或仍被组合引用时不可删号。换会话后登录状态回到未验证，首次采集成功才转为正常。

节点：名称、本机直连/代理、地域、代理的出口模式（固定出口/会话保持）、出口 IP 与有效期、状态。有效期内 IP 不变。

节点名可单独修改，不影响线路与已填出口 IP，名称在全局唯一。换连接可以改线路类型、地域与出口模式，但会清掉出口验证并要求重填出口 IP；代理地址不回显，所以改代理节点的任何一项都要重新填一次地址。

组合由使用者显式建立并持久化：账号绑到节点上，平台由账号推导，采集时认领一条任务独占该组合、交回后再领。限频按「平台 + 出口 IP」计，界面对同出口的多个节点提示共享该平台 IP 预算。

资源页顶部按当前库内状态列出缺口（缺账号、缺出口 IP、未绑账号），每条指向对应节点的设置入口。

### 配置（短效补货）

水位与代理商目前只是存配置：**系统还没有按水位向代理商拉号的实现**，因此界面不展示「当前可用短效数」这类恒为 0 的指标，页顶明确说明填了不会多出节点。水位可编辑国内、国外、香港的最少可用数。代理商：名称、启用、优先级、可供地域，API 凭证只写不回显。与资源页分离，避免日常分配与供应商配置搅在一起。

### 查看运行

以 **账号 + 出口 IP** 为单元，标明能采的平台/地域、是否空闲、当前认领的方向和当前页商品。同一出口上不同平台工人分开展示。只读诊断，不可清冷却。

### 查看行情与映射

市场数据以 Steam 标准商品为中心，一行展示各平台可比较的人民币行情。求购明确显示“最高求购价”，出售明确显示“最低出售价”，同时显示采集时间和最新尝试状态。最新尝试失败、为空或不可用时，最近有效价格只能作为带原时间的历史值展示，不能保持成看似正常的当前价格。

**没有「映射失败」列表**：按 [REFERENCE.md](./REFERENCE.md) 的映射顺序，采集要么落到一个确定的商品（名称没命中就新建），要么整页提交失败，系统不产生也不持久化「映射失败」这类行。因此这一页只展示行情，不提供失败项列表、模糊匹配或批量确认。

### 规则与详情

**规则引擎尚未接入**：后端没有规则表也没有规则接口，详情采集能力对外报告为 `detail_unavailable`。规则页因此只是能力状态页，如实说明当前能力值与没有规则列表的原因，不做规则增删改查，也不展示假的规则或快照。

接入后这一页才展示规则是否启用、条件版本、最近触发时间和详情任务结果；详情页展示指定平台、商品和方向的订单快照、采集时间和完整性，部分快照必须显著标明，不能覆盖最近一次完整结果。

## 状态呈现

所有数据页面都必须处理以下界面状态：

- 加载中：保留页面结构并明确当前正在读取什么。
- 空状态：说明是尚未配置、确实没有数据，还是筛选后无结果。
- 错误状态：保留最近成功数据时，同时显示其时间和已过期状态。
- 禁用状态：说明操作为何不可用以及应先完成哪一步。
- 部分状态：明确已覆盖范围、未完成原因和最后成功时间。

颜色不能作为唯一状态信号；状态同时使用文字和必要图标。表单使用永久标签，不用占位文本代替字段名。主要表格支持紧凑筛选和稳定列顺序，避免卡片套卡片。

控制台以桌面浏览器为主要使用环境。窄屏至少保证概览、采集停止和异常查看可用，但首版不为移动端重做完整资源分配工作流。

## 危险操作

以下操作必须先检查占用并要求明确确认：

- 关闭正在运行的采集方向。
- 删除或替换占用中的平台账号。
- 删除占用中的访问节点，或替换其代理认证。
确认框写明影响对象与后续状态。仍被组合引用时拒绝删除，并给出资源页入口。

## 本地控制面安全

控制台只加载同源静态资源，不使用 CDN 或第三方脚本。所有读取使用无副作用 GET；所有修改使用 JSON POST，并携带服务端提供的 CSRF 令牌。后端同时校验 `Host` 和同源 `Origin`，不开放跨域响应，避免恶意网页借浏览器访问本机控制接口。

查询页面和浏览器日志不得出现原始账号会话或代理密码。账号会话与代理认证信息只在新增或明确替换时提交；保存后页面只显示别名、状态、最近验证时间和占用信息。

控制台首次加载时从同源安全上下文 GET 取得短期 CSRF 令牌；服务端同时设置 `HttpOnly`、`SameSite=Strict` 控制会话 Cookie。生成的 TypeScript 客户端统一把令牌放入专用请求头。会话或令牌过期后重新获取，业务 POST 不静默重放。

## 首版范围

首版必须完成：

- 账号绑到节点；工人路由只看平台和地域。
- 概览按游戏启停各平台方向（无手填并行）。
- 账号、节点资料（长/短效、地域、出口验证）与组合展示。
- 短效池三地域水位与多代理商配置（样机可 mock；真拉号后置）。
- 运行页：账号 + 出口 IP、是否空闲、当前方向与当前页商品。
- 跨平台人民币行情。
- 最小规则与详情快照（规则引擎接入后才有，当前只有能力状态页）。
- 危险操作占用检查与确认。
- 本机 Host、Origin、CSRF、CSP 与敏感字段保护。

首版不做：

- 桌面客户端或额外 Node 后端。
- 账号自动轮换。
- 真实代理商 API 拉号与探测闭环（样机先露水位与配置）。
- 手动清冷却、绕过限频。
- 模糊映射与复杂规则编辑器。
- 趋势、套利、通知、多用户权限。

## 页面验收标准

- 能把账号绑到节点；地域不允许的平台不能领任务。
- 概览只开关、不填并行；开着的方向有健康工人就会补货。
- 开关不把受理当完成；关闭可见停止过程，未完成任务丢掉。
- 仍被组合引用的账号、节点不可强删。
- 运行页能说明账号、出口 IP、当前方向和当前页商品。
- 行情不混淆 bid/ask、空/失败。
- 真 API 接通后不使用演示数据冒充完成。
- GET 无副作用；缺 CSRF 或跨源 POST 拒绝；不回显会话原文。
