# buff-go

buff-go 是面向系统所有者的本机 Steam 行情采集系统。它通过 Web 控制台管理平台账号、网络节点和采集方向，持续记录 Steam 在售与求购摘要，并在行情与商品详情中呈现最新尝试、最近有效价和近 30 天变价。

系统只处理两个市场方向：

- **出售（ask）**：通过 Steam 搜索发现商品，记录最低出售价。
- **求购（bid）**：按已经发现的商品读取订单簿，记录最高求购价。

金额只接受明确的人民币数据，并以人民币分整数保存。

## 从配置到结果

1. 打开本机控制台，在资源页创建 Steam 账号和直连或代理节点。
2. 为节点记录公网出口 IP、有效期和地域，再将账号绑定到节点。
3. 在概览添加 Steam 游戏并开启出售方向；系统通过搜索分页发现商品，同时写入标准商品目录和最低出售价。
4. 需要求购价时开启求购方向；系统按出售方向已经发现的目录逐一读取订单簿，记录最高求购价。
5. 在运行页查看组合、当前任务和最近提交批次，在行情与商品详情中查看采集结果。
6. 关闭方向后等待停止完成；未完成任务被清理，已经保存的行情继续保留。

出售方向是商品发现入口，求购方向不会发现新商品。商品级金额或响应语义校验失败、明确空结果或不可用结果会成为最近尝试，但不会把上一次有效价格伪装成本次结果；网络、登录和整页解析失败会重试，不会批量改写行情。

待执行任务持续保存在 PostgreSQL 队列中，队列本身不决定请求速度。实际吞吐由可同时工作的账号节点组合数决定；一个组合完成后立即续领，不等待其他慢组合。Steam 出售搜索和求购订单簿分别按“接口 + 账号 + 出口 IP”限频，不存在跨平台或跨接口的统一总频率桶。

## 当前能力边界

- 执行 Steam 出售搜索和 Steam 求购订单簿摘要采集。
- 可以保存 BUFF、IGXE 账号及地域组合，但不执行对应平台采集。
- 代理商与地域水位只保存配置，不自动获取代理、探测出口或补充节点。
- 规则页只展示 `detail_unavailable`，没有规则引擎、详情任务或完整订单快照。

## 运行形态

系统采用 Go 模块化单体。一个进程同时提供本地 API、嵌入式 Vue 控制台和常驻采集器；PostgreSQL 保存配置、任务、限频、行情与恢复状态，生产环境不需要额外运行 Node 服务。
